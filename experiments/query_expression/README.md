# Query Expression Experiment

This lightweight package reproduces the six frozen Dense-only query-expression groups from the full `query_expression_experiment` research archive. It uses **pretrained** multilingual E5, not the project-specific fine-tuned E5 checkpoint. The original project workflow is unchanged.

## Files and scope

- `run_experiment.py`, `encode_queries.py`, `search_and_evaluate.py`: one entry point and separate encoder/search processes.
- `evaluation.py`: unchanged shared citation-set evaluator from the experiment's project snapshot.
- `config.json`, `requirements.txt`: portable paths and tested dependency versions.
- `inputs/`: all 30 frozen query texts (10 queries, three expression views), full official-validation gold and the original freezing record.
- `validation/`: original transformation self-review and index-check evidence. These archived checks are not new packaging experiments.
- `results/`: original consolidated candidates, all 24 Top-K summaries, 240 per-query scores, compact comparison, gold-rank changes, budget counts, timing components and failure rates. All six groups, including negative results and both controls, are retained unchanged.
- `provenance/`: model/index identities, exact external locations, original run/configuration/split records, prior baseline comparison and retained-file hashes.

The full archive retains duplicate project/data snapshots, original authoring inputs, language-classifier code and samples, logs, query/probe vectors, search-resume cache, raw passage rankings, redundant per-group candidate/prediction exports, and the Cross-Encoder passage cache. These are not needed to rerun frozen-query retrieval and citation evaluation. No model or full index is copied here. Saved candidates remain in `results/all_candidates.csv`; standard per-group CSVs are regenerated by a reproduction run.

## Environment and external artifacts

Tested: Python 3.12.14, PyTorch 2.6.0+cu126, Transformers 4.49.0, NumPy 1.26.4, pandas 2.2.3 and faiss-cpu 1.10.0 on Windows. The original run used float32 query encoding, one query per forward pass, seed 760 and four FAISS threads. CPU is supported with `--device cpu`; different devices may slightly change tied rankings and timing.

In a dedicated environment, install the tested CUDA wheel and then the small dependency list:

```bash
python -m pip install torch==2.6.0 --index-url https://download.pytorch.org/whl/cu126
python -m pip install -r requirements.txt
```

For a CPU-only environment use the PyTorch CPU wheel index instead of `cu126`. SentenceTransformers and the language classifier are not runtime dependencies of this package.

Set `model_dir`, `index_dir` and `corpus_map` in `config.json`, or override them on the entry command. Relative paths resolve against this package, not the current working directory. The delivered defaults reference `../../results/external_artifacts/e5_experiment/`: `models/base`, `indexes/base` and `data/corpus.sqlite`. Portable artifact locations are listed in `provenance/artifacts.json`. Keep `corpus_snapshot_sha256.json` beside the mapping and keep **all** original index shards, `manifest.json` and `complete.json` unchanged. Archived absolute `model_path` strings are descriptive; runtime matching uses content hashes and configured paths. Use the base encoder/index, not `epoch_2`.

The OpenMP repair is retained: PyTorch query encoding and FAISS search run in different subprocesses. Do not set `KMP_DUPLICATE_LIB_OK`; the scripts reject that bypass. E5 uses `query: `, attention-mask mean pooling and L2 normalization; existing documents use `passage: citation title text`. The encoder verifies model/index identity. Full reproduction verifies every shard hash, the mapping hash and corpus identity, preserving global row IDs and exact citation deduplication.

## Commands

From this directory, check saved results without loading a model or searching the index:

```bash
python run_experiment.py --verify-only
```

To additionally check existing model/tokenizer hashes, index manifests/shard presence and candidate-to-corpus row IDs:

```bash
python run_experiment.py --verify-only --check-artifacts
```

Run the actual complete frozen-input reproduction only when wanted:

```bash
python run_experiment.py --device auto
```

This writes to `runs/reproduction/` and preserves delivered `results/`. The same command resumes partial shard search; changed configuration requires a fresh `--output-dir`. No training or document re-encoding is performed. Paths can also be supplied using `--model-dir`, `--index-dir`, `--corpus-map` and `--output-dir` (see `--help`). Main new outputs are `runs/reproduction/results/main_comparison.csv`, `metrics.csv`, `per_query_metrics.csv`, `all_candidates.csv`, `query_expr_<group>_candidates_top100.csv`, and `query_expr_<group>_predictions_top<K>.csv`. Candidate and final prediction files have different formats. The candidate CSVs retain the existing reranker's `query_id,rank,doc_id,citation,source_type` columns; Cross-Encoder scoring is not performed here.

## Reading the results

`en`, `de`, and `legal_original` use the original English, full German translation, and German legal concepts **plus the complete original English facts**. `en_de_rrf` uses equal-weight reciprocal-rank fusion (k=60) of two Top-100 citation pools. Each single view searches 1,000 passage rows. Controls search the English query to 2,000 rows (`en_deep2x`) or execute the original search twice before fusion (`en_repeat2x`). Every final group has exactly 100 unique citations per query. Offline translation authoring/self-review is recorded; per-query translation-generation latency was not measured and the review was not independently human validated.

The saved comparison covers only ten historically tuned official English validation queries, with **full gold** and query-macro citation recall/F1. German translation lowers Recall@100 from 0.014 to 0.004; concept-plus-original and budget controls match the English aggregate scores; fusion preserves Recall@100 but lowers Macro F1@10 from 0.0100 to 0.0057. German improves one German gold's rank but loses a French gold; the eight other queries have no gold in Top-100. All six candidate pools remain court-only (law gold hits 0/149). This does not establish a causal language explanation or solve source bias. The prior project baseline is a historical comparison; the six group scores are newly executed retrieval from the original study. The original monolithic index was unavailable; all six groups share the archived full pretrained index. No untouched English test-set claim is made. Fine-tuned BGE weights were unavailable, so neither Cross-Encoder nor combined final-pipeline gains were evaluated.

Packaging verification is recorded in `validation/package_checks.json`: imports, CLI, relocation, saved-data rescoring and candidate format checks only. It does not represent another full retrieval experiment, index scan, training run or Cross-Encoder run.
